# 校园二手 · 交易与任务平台

一个给同学用的轻量交易平台：**闲置物品交易** + **跑腿/帮忙任务发布**。

两条线共用同一套状态机——钱先由平台托管，事办完才放款。

---

## 现在做到哪一步了

**第一阶段：账本核心 ✅**（就是你现在看到的这个东西）

先把「钱怎么算不出错」解决掉。因为交易系统最难的地方不在页面好不好看，
而在于**并发的时候钱会不会算错**。

已经防住的坑：

| 坑 | 现象 | 防法 |
|---|---|---|
| 余额被扣成负数 | 两个请求同时下单，都以为钱够 | SQL 里 `WHERE (balance - frozen) >= 金额`，判断和扣减焊死在一句里 |
| 同一订单重复扣款 | 手抖点两次"支付"，扣两遍 | 订单号做主键 + 流水表 `UNIQUE(order_id, action)` |
| 重复结算 | 同一订单结算两次，卖家收两份钱 | 结算前校验订单状态，状态不对直接拒绝 |
| 余额语义混乱 | 冻结的钱被算两遍，对账对不上 | 约定 `balance` 是总资产、`frozen` 是其中被锁的部分 |

## 为什么金额用「分」

金额一律存整数（分），**绝不用小数**。

因为 `0.1 + 0.2 === 0.30000000000000004`——钱上不能有这种误差。
所有对外的接口用「元」，进出账本时乘 100 转成整数。

## 重要边界说明

**这是个人练手项目，不是真实交易平台。**

- ✅ 可以：本地跑、给同学演示、记账、放进作品集
- ❌ 不可以：真收钱、真提现、让平台过手真实的钱

原因：个人无法取得支付业务资质，平台代收代付资金会触及
「资金池」相关的法律红线。这个项目的「结算」是**纯记账演示**，
所有金额都只存在于本地数据库里。

**这个项目不适合用于任何真实资金流转场景。**
